This documentation is organized by purpose so product decisions, engineering references, operational runbooks, design guidance, and external research are no longer mixed together.

## Sections

- `product/` explains what ValGuide is, who it serves, and the language the team should use.
- `engineering/` contains implementation architecture, content model references, engineering patterns, and technical reference docs.
- `operations/` covers admin, routing, analytics, notifications, and internal workflows.
- `design/` contains UX principles, notification guidance, review material, and UI behavior references.
- `research/` is archival material: competitor analysis, screenshots, and external reference collections used for comparison and inspiration.

## Rules Of Thumb

- If a document defines how the product should work, keep it out of `research/`.
- If a document is primarily an external example or imported source material, keep it in `research/`.
- If a document becomes historical rather than authoritative, move it out of the main first-party sections.
